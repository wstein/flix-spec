# Gradle consumer integration

Plugin ID: `io.github.wstein.flix-spec`. Published to the same Maven repository as
the data and runner, with plugin marker metadata (not the Gradle Plugin Portal).
The initial tested platform is Gradle 9.7.1 and Java 21. The plugin launches the
runner using a Java 21 toolchain. It implements no comparison logic.

`settings.gradle.kts`:

```kotlin
pluginManagement {
    repositories {
        maven("https://wstein.github.io/flix-spec/maven")
        gradlePluginPortal()
    }
}
```

`build.gradle.kts` (replace the three version placeholders with published versions):

```kotlin
plugins { id("io.github.wstein.flix-spec") version "<plugin-version>" }

repositories { maven("https://wstein.github.io/flix-spec/maven") }

flixSpec {
    runnerVersion.set("<runner-version>")
    specVersion.set("<data-version>")
    actualDirectory.set(layout.buildDirectory.dir("adapter-output"))
    projectionMap.set(layout.projectDirectory.file("conformance/projection-map.json"))
    // Default sourceRoot is the extracted bundle, for adapters parsing its fixtures.
    // Override only if projection source paths refer to a different source tree:
    // sourceRoot.set(layout.projectDirectory)
    // accepted.set(layout.projectDirectory.file("conformance/accepted.json"))
    // depthFloor.set(90) // choose a measured floor appropriate to your adapter
}

tasks.named("flixSpecCheck") { dependsOn("emitAdapterProjections") }
tasks.named("emitAdapterProjections") { dependsOn("prepareFlixSpec") }
```

`emitAdapterProjections` is your own task, not generated by the plugin. It should
parse fixtures from `build/flix-spec/spec`, declare its inputs and outputs, and
write projected JSON into `actualDirectory`. An empty or missing directory fails.
Do not configure the adapter's inputs as the output of `flixSpecCheck` (that would
create a dependency cycle).

## Tasks and properties

- `prepareFlixSpec`: resolves and synchronizes the bundle into `build/flix-spec/spec`.
- `flixSpecCheck`: compares outputs and writes `build/reports/flix-spec/report.json`
  and `report.html`. HTML is produced on comparison failure too, never from stale
  reports after invalid input.
- `check`: depends on `flixSpecCheck`.

Both version pins are required and independent. Repositories are entirely
consumer-configured. `baseline`, `recoveryBaseline`, `diagnosticBaseline`,
`depthFloor`, and `recoveryDepthFloor` default to zero. Optional `accepted` and
`projectionMap` files are tracked task inputs. Capabilities are declared in the
consumer's projection map, not duplicated in the Gradle configuration.

The task distinguishes runner exit 1 (conformance failure) from exit 2 (invalid
input). It tracks the runner classpath, specification, actual projections, source
`.flix` files, maps, accepted sets, thresholds and toolchain. Configuration-cache
reuse and incremental input invalidation are exercised with the actual runner in
Gradle TestKit. The design uses injected `ExecOperations`, following Gradle's
[configuration-cache requirements](https://docs.gradle.org/current/userguide/configuration_cache_requirements.html).

The plugin itself is published as `io.github.wstein:flix-spec-gradle-plugin`.
For local publication use `:tools:gradle-plugin:publish` with
`-PflixSpec.publishRepo=<repository URI>`, exactly as for the runner.

The [executable Gradle example](../examples/gradle-consumer/build.gradle.kts)
checks the reference against itself to demonstrate wiring, not an independent
parser. `tools/gradle-plugin/acceptance.sh <local Maven repository> <version>` runs
it outside the checkout and resolves the actual published plugin marker and jar.
CI executes both this distribution check and the TestKit regression tests.
