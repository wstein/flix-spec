# Flix v0.77.0 migration and repository review

The oracle advances from Flix v0.76.0 (`f2d4678c20bff1242f4cad5e23144db91027b762`)
to v0.77.0 (`4a5b60a31ac03bb762f68b554a0fc2b6f4d982b9`). The package version is `0.77.0`.

The official [release artifact](https://github.com/flix/flix/releases/tag/v0.77.0) has SHA-256
`20007d79f97b696ba388113e2a4235227691d33a00bfa669f2316b37a7b14201`. It contains 20,103 entries
and is 39,157,744 bytes. The artifact remains recorded as digest-only; this migration does not
establish build provenance linking its bytes to the source commit.

## The Reader phase is gone

This is the only breaking change, and it is in the API rather than the vocabulary.

v0.77.0 deletes `language/ast/shared/Input.scala` and `language/phase/Reader.scala`. The compiler
now builds its `ReadAst.Root` directly from `Source` values, as `Flix.scala` does with
`ReadAst.Root(getSources.map(src => src -> ()).toMap)`. `Input`, `Reader.run` and
`AvailableClasses.empty` no longer exist, and this repository drove all three: the parser adapter
and the corpus runner both failed to compile against the new jar.

Both now construct the `Source` themselves — read the bytes with the compiler's own
`defaultCharset`, wrap them in `Source.fromString(SourceName.PathName(path), Origin.User,
SecurityContext.Plain, text)` — which is exactly what the deleted Reader did for a real file. The
projected trees are unaffected.

One behaviour had to be reconstructed rather than ported. `Reader.run` was the only thing that
reported a file as unreadable, and `ast/reachability.json` counts those deliberately in
`filesUnreadable`. The corpus runner now catches the read failure itself, because a count inferred
from a phase that no longer runs would silently become zero.

## Vocabulary

Purely additive. Nothing was removed or re-parented.

- **`UsesOrImports.Package`** (TreeKind 191 → 192). `use()` now recognises a package path:
  `use flixball::Game.Board` and `use flixball::{Game, Board}`.
- **`ColonColonTight`** (TokenKind 158 → 159). `::` written without surrounding whitespace lexes
  as a distinct token. Tight `::` is the package-path separator; spaced `::` remains list cons.
  Writing the separator with whitespace is now a `Malformed` error carrying the hint
  *"Write `::` without whitespace on either side"*.

### `ColonColonTight` was invisible to every gate, and that is the point of the new fixtures

Upstream leaves `("::", TokenKind.ColonColon)` in the `Operators` table and decides tightness in
hand-written dispatch outside every table, so nothing in a table-driven extraction changes. The
committed fixture suite contained no tight `::` at all, so `fixtures/raw` and `fixtures/expected`
regenerated byte-identically across the split. `LosslessCheck` reads only a token's `text`, never
its `token`, so a pure kind relabel is invisible to it by construction. And the vocabulary digest
catches the *addition* of a name, never the *re-partitioning* of an existing one's extension.

A consumer matching `ColonColon` today would therefore have stopped matching `a::b` with every
gate in this repository still green. Two fixtures close that:

- `fixtures/positive/declarations__use-with-a-package-path.flix` — exercises `UsesOrImports.Package`
  and `ColonColonTight` together, in both the `.Board` and `{Game, Board}` forms.
- `fixtures/negative/declarations__package-path-separator-must-be-tight.flix` — pins the spaced
  form to `ColonColon` plus the `Malformed` diagnostic, so the distinction between the two tokens
  is asserted rather than assumed.

Before these, `ast/status.json` reported `UsesOrImports.Package` as *neither exercised nor
explained* — the repository's own gate naming the gap.

## Corpus

Upstream removed the `examples/package-manager` tree and reorganised a few example files. The
corpus moves from 900 files (712 main, 188 examples) to 893 (713 main, 180 examples). 892 of 893
parse without error, and all 892 are lossless.

## Curated evidence

Every citation in `ast/transparency.json`, `ast/unattachable.json` and `defects/ledger.json` was
re-read against the new commit: all 53 moved, since deleting the Reader shifted early lines up by
roughly 8 and the Parser2 additions shifted later ones down by roughly 25. Ambiguous relocations
(identical lines occurring several times) were resolved by matching surrounding context, not by
offset. FLIX-0001 still reproduces at this pin: `Parser2.param()` still initialises `var kind` to
`Predicate.ParamUntyped` (4018) and overwrites it three lines later (4021), and `Weeder2` still
matches on the dead kind in two places.

## Validation

`./gradlew test` (125 tests) and `./tools/project/verify.sh` both pass end to end. Normalisation
removes 2,285 of 4,449 nodes (51.4%) across 146 fixtures; `ast/status.json` reports 0 unknown
TreeKinds and 0 unknown TokenKinds.

## What consumers must do

1. Update the exact pin check to `4a5b60a31ac03bb762f68b554a0fc2b6f4d982b9`.
2. Accept the two new vocabulary names, and **split any rule that matches `ColonColon`** — a
   lexical consumer that scopes `::` as one thing will now mis-scope package paths.
3. Re-measure: the fixture suite is 146 files and the transparency contract removes far more than
   it did, so every `fixtureRevision` and every baseline in every consumer is stale.
